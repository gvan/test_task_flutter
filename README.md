# 3

При зміні сортування виникала наступна проблема:
- маємо початкове сортування, на першій позиції показується товар X;
- змінюємо сортування, на першій позиції показується товар Y;
- при кліку на товар Y відкривається екран з товаром X.

Проблема була в тому, що віджетом для товару є StatefulWidget. Об'єкт товару, який передавався в колбек кліку, був збережений в стейті окремим полем і ініціалізувався в initState. При зміні сортування айтемів на першій позиції замість товару X опинявся товар Y. build() метод викликався, тому на першій позиції ми бачимо дані товару Y, але initState() метод не викликався, тому змінна _selectedItem не перевизначалась і зберігала в собі товар X. 

Виклик initState() не відбувався через те, що при виклику Widget.canUpadte() для старого і нового віжетів перевіряється тип і ключ на рівність. Оскільки тип віджету однаковий і ключ дорівнює null, то canUpdate повертає true і новий стейт для віжета на першій позиції не створюється.

Рішенням було визначити ключ для кожного товару використовуючи id товару. Можна передавати об'єкт widget.item в onPressed() замість _selecteItem, але збереження товару в стейті може бути зроблено для реалізації майбутньої логіки, наприклад, додавання коментара до товару з полем вводу всередині айтема списку.
